# AI watermarking and content provenance (C2PA, SynthID)

## Summary
Two complementary ways to say "this content was made by AI": **provenance metadata** (C2PA Content Credentials), a signed manifest attached to a file that records who made it and how, and **watermarks** (e.g. Google DeepMind's SynthID, or green-list text watermarks), signals hidden in the content itself that a key holder can detect later. Metadata is precise but easy to strip; watermarks survive some edits but are statistical and can be removed or diluted. Post-hoc "AI detectors" that use neither are unreliable and should not drive high-stakes decisions.

## Key concepts
- **C2PA / Content Credentials**: an open standard from the Coalition for Content Provenance and Authenticity. A **manifest** holds assertions (creator, tool, "AI-generated", edit actions, ingredients), is cryptographically signed with an X.509 certificate, and is bound to the asset by hashes. Editing tools can add new manifests, giving a chain of history.
- **Hard vs soft binding**: hash binding breaks on any byte change; soft bindings (a watermark or fingerprint) let a verifier look up a manifest after metadata was stripped.
- **What C2PA proves**: that a signer made claims about this file and the file was not altered since. It does not prove the claims are true, and missing credentials prove nothing.
- **Generation-time text watermark (Kirchenbauer et al.)**: at each step a key and the previous token pick a "green list" of the vocabulary; generation adds a small bonus to green logits. Detection counts green tokens and runs a z-test; it needs the key, not the model.
- **SynthID**: Google DeepMind's watermarking for AI-generated images, audio, video and text. SynthID Text uses tournament sampling with keyed functions; it is published in Nature, open-sourced as a reference implementation, and available in Hugging Face Transformers as a logits processor configured with secret `keys` and an `ngram_len`.
- **Robustness vs quality vs detectability**: stronger watermarks are easier to detect and survive more edits but distort outputs more; text watermarks need enough tokens and enough entropy (low-entropy answers like code or facts carry little signal).
- **Post-hoc detectors** (classifiers of "AI style"): OpenAI withdrew its own AI-text classifier in 2023 citing low accuracy; paraphrasing defeats detectors and watermarks alike (Sadasivan et al.).
- **Regulation**: EU AI Act Article 50 requires providers of generative systems to mark synthetic audio, image, video and text in a machine-readable, detectable way, and deployers to disclose deepfakes; the AI Act timeline lists 2 August 2026 for these transparency duties. Check the current Commission guidance and code of practice for what counts as compliant marking.

## When to use / scenarios
- Your product generates images, audio or video: attach C2PA manifests at generation time and, where available, add a watermark as a soft binding.
- You self-host an LLM and want to show later that a given text came from it: generation-time text watermark with a private key.
- Newsrooms and platforms checking uploads: read Content Credentials when present; treat absence as unknown.
- Real-world: a marketing-image generator signing every output as AI-generated; a stock-photo site displaying Content Credentials; a public-sector chatbot watermarking letters it drafts.
- Not when: deciding guilt (academic misconduct, fraud) from a detector score alone; false positives fall on real people, and detectors have been reported to misfire more on non-native writing.

## Setup & code
A green-list text watermark and its z-test detector on a toy language model, plus the effect of length and edits. NumPy and stdlib only.

```python
import hashlib

import numpy as np

V, GAMMA, DELTA = 1000, 0.25, 2.0            # vocab, green fraction, logit bonus
KEY = b"secret-watermark-key"                 # whoever holds the key can detect (and forge)
rng = np.random.default_rng(0)
LM = rng.normal(scale=2.0, size=(V, V))       # toy LM: next-token logits given previous token


def green_list(prev):
    """Pseudo-random green set seeded by the key and the previous token."""
    seed = int.from_bytes(hashlib.sha256(KEY + prev.to_bytes(4, "little")).digest()[:8], "little")
    return np.random.default_rng(seed).permutation(V)[: int(GAMMA * V)]


def generate(n, watermark, rng):
    toks = [int(rng.integers(V))]
    for _ in range(n):
        logits = LM[toks[-1]].copy()
        if watermark:
            logits[green_list(toks[-1])] += DELTA  # soft watermark: nudge, don't force
        p = np.exp(logits - logits.max())
        toks.append(int(rng.choice(V, p=p / p.sum())))
    return toks


def z_score(toks):
    """One-proportion z-test: are there more green tokens than chance (GAMMA)?"""
    hits = sum(t in set(green_list(prev)) for prev, t in zip(toks, toks[1:]))
    T = len(toks) - 1
    return (hits - GAMMA * T) / np.sqrt(T * GAMMA * (1 - GAMMA))


def edit(toks, frac, rng):
    """Crude paraphrase attack: replace a fraction of tokens with random ones."""
    toks = list(toks)
    for i in rng.choice(len(toks), int(frac * len(toks)), replace=False):
        toks[i] = int(rng.integers(V))
    return toks


wm, plain = generate(200, True, rng), generate(200, False, rng)
print(f"no watermark, 200 tokens:   z = {z_score(plain):5.1f}")
print(f"watermarked, 200 tokens:    z = {z_score(wm):5.1f}   (z > 4 is a common threshold)")
print(f"watermarked, first 10 only: z = {z_score(wm[:11]):5.1f}   (z grows with sqrt(length))")
for frac in (0.2, 0.4, 0.6):
    print(f"watermarked, {frac:.0%} of tokens edited: z = {z_score(edit(wm, frac, rng)):5.1f}")
```
The detector needs only the key and the tokens. Short texts and heavy edits push the score toward chance, which is the core limit of every text watermark.

SynthID Text in Hugging Face Transformers (needs a model download; parameter guidance from the HF blog: 20-30 random integer keys, `ngram_len` 5 as a default):

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, SynthIDTextWatermarkingConfig

MODEL = "<a causal LM repo id, e.g. from models/google-gemma.md>"
tok = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForCausalLM.from_pretrained(MODEL)

wm_config = SynthIDTextWatermarkingConfig(
    keys=[654, 400, 836, 123, 340, 443, 597, 160, 57, 29, 590, 639, 13, 715, 468, 990,
          966, 226, 324, 585, 118, 504, 402, 721, 485, 945, 389, 120, 233, 744],  # keep secret
    ngram_len=5,
)
inputs = tok(["Write a short note about tides."], return_tensors="pt")
out = model.generate(**inputs, watermarking_config=wm_config, do_sample=True, max_new_tokens=100)
print(tok.batch_decode(out, skip_special_tokens=True)[0])
```
Detection with SynthID Text uses a separately trained Bayesian detector; follow the Transformers SynthID docs for training and running it.

For images and video, the Content Authenticity Initiative's open-source SDKs (`c2pa-rs` with the `c2patool` CLI, plus Python and JavaScript bindings) read, sign and verify manifests; signing needs a certificate whose trust chain verifiers accept.

## Choosing / trade-offs
| | C2PA metadata | Watermark | Post-hoc detector |
|---|---|---|---|
| Needs cooperation of generator | Yes | Yes | No |
| Survives screenshot / re-encode | No (unless soft binding) | Often, partly | n/a |
| Survives paraphrase / heavy edit | No | Weakly | Weakly |
| Evidence strength | Signed claim | Statistical (p-value) | Probabilistic guess |
| Who can verify | Anyone with the manifest | Key holder (or vendor service) | Anyone |

- Use both layers: metadata for rich, verifiable history; watermark as a fallback when metadata is stripped.
- Key management: whoever holds a watermark key can detect and potentially forge marks; treat keys as secrets.

## Gotchas
- Social platforms and messaging apps often strip metadata on upload, so C2PA alone rarely survives redistribution.
- A watermark only identifies content from models that apply it; open-weights models can be run without one.
- Text watermarks weaken on short, low-entropy or translated outputs; set minimum lengths before trusting a score.
- Report detection as evidence with a false-positive rate, not a yes/no verdict.
- Signing certificates expire and can be revoked; plan rotation and trust-list membership.
- Regulatory marking duties may apply to the provider and the deployer differently; get legal review ([[ai-security-privacy-compliance]]).
