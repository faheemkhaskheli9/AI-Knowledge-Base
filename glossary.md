## 0-9

- **3D generation** - creating meshes or Gaussian splats from text or images. [[3d-generation-models]]

## A

- **A2A (Agent2Agent) protocol** - an open protocol for agents built by different vendors to discover each other's capabilities and exchange tasks and messages. [[a2a-protocol]]
- **A/B test** - randomly split users between two variants and compare a pre-chosen metric with a significance test before declaring a winner. [[statistics-and-ab-testing]]
- **Abliteration** - removing a behaviour (usually refusal) from an open-weight model by orthogonalizing the weights that write to the residual stream against that behaviour's direction. [[refusal-direction-and-abliteration]]
- **acc_norm** - multiple-choice accuracy where each answer's log-likelihood is divided by its length before picking the best, so longer answers are not penalised. [[lm-evaluation-harness-and-lighteval]]
- **Accelerate (Hugging Face)** - a library that runs the same PyTorch training loop on CPU, one GPU or many with minimal code changes. [[pytorch-lightning-and-accelerate]]
- **Acceptance length (speculative decoding)** - mean tokens a serving engine emits per target-model verification pass, including the bonus token; 1.0 means every draft was rejected. [[speculative-decoding-in-serving]]
- **Activation function** - the non-linearity applied after a layer's linear map (ReLU, GELU, SiLU, sigmoid); without it stacked layers collapse into one linear map. [[activation-functions]]
- **Active learning** - the model picks the unlabeled examples it is least sure about for humans to label next, to get more accuracy per label. [[semi-supervised-and-active-learning]]
- **Actor-critic** - an RL method where a policy (actor) is updated using a learned value function (critic) as a baseline to cut gradient variance. [[actor-critic-from-scratch]]
- **AdaBoost** - boosting that re-weights training examples so each new weak learner focuses on the ones the previous learners got wrong. [[adaboost-from-scratch]]
- **Adam / AdamW** - an optimizer with per-parameter step sizes from running averages of gradients and squared gradients; AdamW decouples weight decay from the update. [[optimizers]]
- **Adversarial example** - an input changed by a small, often imperceptible perturbation that makes a model predict wrongly. [[adversarial-examples-and-robustness]]
- **Agent** - an LLM running in a loop that chooses tools, observes results and decides when the task is done. [[agents]]
- **Agent evaluation** - measuring agents on task success and on the trajectory of steps taken, often in sandboxed benchmarks. [[agent-evaluation]]
- **Agent framework** - a library for building agent loops, tools, memory and orchestration (LangGraph, Agents SDKs). [[agent-frameworks]]
- **Agent memory** - state an agent keeps beyond one context window: working memory, past episodes and learned facts, stored and retrieved on demand. [[agent-memory]]
- **Agent skill (SKILL.md)** - a folder of instructions and scripts an agent loads only when a task matches its short description (progressive disclosure). [[agent-skills]]
- **Agentic RAG** - retrieval where the model decides when and what to search, possibly over several rounds, instead of one fixed retrieve-then-generate step. [[advanced-rag]]
- **AI Act (EU)** - the EU regulation that sorts AI systems by risk tier and attaches obligations (documentation, oversight, transparency) to each tier. [[ai-regulation-checklist]]
- **AIC (Akaike information criterion)** - a model-selection score that rewards fit and penalizes the number of parameters; lower is better. [[arima-from-scratch]]
- **ALiBi** - a position method that adds a head-specific penalty proportional to query-key distance to attention scores instead of using position embeddings. [[positional-encodings]]
- **Annotation queue** - a list of production traces assigned to human reviewers with a fixed scoring rubric, filled from negative feedback, a random sample and high-risk cases. [[user-feedback-and-human-review]]
- **Anomaly detection** - finding points that do not fit the pattern of most of the data, usually without labels for the anomalies. [[anomaly-detection]]
- **API key (LLM)** - the secret that authenticates calls to a model provider's API; keep it in environment variables or a secret store, never in code. [[api-sdk-setup]]
- **Apriori** - an algorithm for frequent itemsets that prunes candidates using the fact that every subset of a frequent itemset is also frequent. [[apriori-from-scratch]]
- **ARIMA** - a classical forecasting model combining autoregression, differencing to remove trend and a moving-average error term. [[arima-from-scratch]]
- **Association rule** - an "if A then B" pattern mined from transactions and scored by support, confidence and lift. [[association-rules-market-basket]]
- **Attention** - a layer where each token builds its output as a weighted mix of other tokens' values, with weights from query-key similarity. [[transformers-and-attention]]
- **Audio classification** - labelling audio clips or events, such as sirens or speech, often with spectrogram-based models. [[audio-classification-and-sound-events]]
- **Autoencoder** - a network trained to reconstruct its input through a narrow bottleneck, so the bottleneck learns a compressed representation. [[autoencoders-and-self-supervised-learning]]
- **Autograd** - automatic differentiation that records the operations of a forward pass and applies the chain rule backwards to get gradients. [[backpropagation-and-autograd]]
- **AutoML** - automated search over models, features and hyperparameters for a given dataset and metric. [[automl]]
- **AWQ** - activation-aware weight quantization: protects the weights that matter most for activations when quantizing an LLM to 4 bits. [[quantization]]

## B

- **Backfill (re-embedding)** - a resumable background job that re-embeds existing records into a new index without overwriting newer dual-written rows. [[embedding-model-migration-and-reindexing]]
- **Bagging** - training many models on bootstrap resamples of the data and averaging them to cut variance; the basis of random forests. [[ensemble-methods]]
- **Bandit (multi-armed)** - repeatedly choosing among options with unknown payoffs while balancing exploration and exploitation. [[multi-armed-bandits]]
- **Batch API** - a provider endpoint that runs many requests asynchronously at lower cost, returning results later instead of in real time. [[batch-inference-and-batch-apis]]
- **Batch normalization** - normalizes each feature over the mini-batch, then rescales with learned parameters; behaves differently at train and inference time. [[normalization-layers]]
- **Batch size** - the number of examples per gradient step; it sets gradient noise and interacts with the learning rate. [[batch-size-and-gradient-noise]]
- **Baum-Welch** - the EM algorithm for fitting HMM parameters from unlabeled sequences, using forward-backward probabilities. [[hmm-from-scratch]]
- **Bayesian network** - a directed acyclic graph of random variables whose edges encode conditional dependencies. [[probabilistic-graphical-models]]
- **Beam search** - decoding that keeps the k most probable partial sequences at each step instead of only the single best one. [[decoding-strategies-from-scratch-numpy]]
- **Benchmark** - a fixed test set and metric used to compare models; scores depend on prompting, contamination and setup. [[reading-ai-benchmarks]]
- **Benchmark contamination** - test items leaking into a model's training data, which inflates its benchmark score. [[reading-ai-benchmarks]]
- **BentoML** - a Python model-serving framework with adaptive batching, worker processes, service composition and Docker packaging of versioned Bentos. [[ray-serve-bentoml-and-litserve]]
- **Bias-variance trade-off** - simpler models err through bias (underfitting), flexible ones through variance (overfitting); total error balances both. [[bias-variance-and-learning-curves]]
- **BLEU** - a machine-translation metric based on clipped n-gram precision against reference texts, with a brevity penalty. [[bleu-and-rouge-from-scratch]]
- **BM25** - a keyword ranking function that scores documents by term frequency (with saturation), inverse document frequency and length normalization. [[bm25-from-scratch]]
- **BPE (byte-pair encoding)** - a tokenizer that starts from bytes or characters and repeatedly merges the most frequent adjacent pair into a new token. [[tokenization]]
- **Bradley-Terry model** - a model that turns pairwise win/loss data into a strength score per player; used for LLM arena leaderboards. [[elo-and-bradley-terry-leaderboard-from-scratch]]

## C

- **C2PA** - an open standard for signed metadata that records where a piece of media came from and how it was edited. [[ai-watermarking-and-content-provenance]]
- **Calibration** - how well predicted probabilities match observed frequencies; a calibrated 0.8 is right about 80% of the time. [[probability-calibration]]
- **Canary rollout** - send a small share of traffic to a new model or prompt and widen it only while its metrics stay healthy. [[ab-testing-and-canary-for-models]]
- **Canny edge detector** - edge detection by smoothing, gradient computation, non-maximum suppression and hysteresis thresholding. [[canny-edge-detector-from-scratch]]
- **Catastrophic forgetting** - a network losing earlier skills when trained further on new data or tasks. [[continual-learning]]
- **Categorical encoding** - turning categories into numbers: one-hot, ordinal, target, hashing or learned embeddings. [[categorical-encoding]]
- **Causal inference** - estimating the effect of an intervention rather than a correlation, using experiments or assumptions about confounders. [[causal-inference-and-uplift]]
- **Chain-of-thought** - prompting or training a model to write intermediate reasoning steps before its final answer. [[prompt-engineering]]
- **Chat template** - the Jinja template shipped with a tokenizer that renders a list of role/content messages into the exact string and special tokens a chat model was trained on (e.g. ChatML). [[post-training-datasets-and-chat-templates]]
- **Checkpoint (model)** - saved model weights and training state, for resuming training or exporting (state_dict, safetensors). [[model-checkpointing-and-export]]
- **Chunking** - splitting documents into retrievable pieces for RAG; chunk size and boundaries strongly affect retrieval quality. [[chunking-strategies]]
- **Classic ML** - non-deep-learning models (linear models, trees, SVMs) usually built with scikit-learn. [[classic-ml-scikit-learn]]
- **Classifier-free guidance** - steering a diffusion model by extrapolating from its unconditional prediction toward its prompt-conditioned prediction. [[diffusion-models]]
- **Claude** - Anthropic's family of LLMs, offered through Anthropic's API and major cloud platforms. [[anthropic-claude]]
- **CLIP** - a model trained on image-caption pairs to embed images and text in one space, enabling zero-shot classification and text-to-image search. [[image-retrieval-clip-search]]
- **Clustering** - grouping unlabeled points so that points in a group are more similar to each other than to points in other groups. [[clustering]]
- **CNN (convolutional neural network)** - a network of learned convolution filters that share weights across positions, suited to images and other grids. [[cnn-and-rnn-architectures]]
- **Code model** - an LLM trained heavily on code, often supporting fill-in-the-middle completion for editors. [[code-models]]
- **Coding agent** - an agent that reads a repository, edits files and runs commands and tests to complete software tasks. [[coding-agents]]
- **Cohen's kappa** - agreement between two raters corrected for the agreement expected by chance; used to check an LLM judge against human labels. [[user-feedback-and-human-review]]
- **Cohere Command** - Cohere's LLM family, offered with its Embed and Rerank models for enterprise RAG. [[cohere-command]]
- **ColBERT (late interaction)** - retrieval that keeps one vector per token and scores a document by summing each query token's best match. [[late-interaction-retrieval]]
- **Cold start (model server)** - the time a new inference replica spends fetching weights, loading them to the GPU and warming up before it can serve. [[model-weight-loading-and-cold-starts]]
- **Collection alias** - a second name for a vector collection that queries use, repointed atomically to cut over to a rebuilt index or roll back. [[embedding-model-migration-and-reindexing]]
- **ComfyUI** - a node-graph interface for building and running local image and video generation pipelines. [[comfyui]]
- **Computer-use agent** - an agent that operates a GUI or browser from screenshots by issuing clicks and keystrokes. [[computer-use-agents]]
- **Concept drift** - a change over time in the relationship between inputs and the target, so a once-accurate model degrades. [[online-learning-and-concept-drift]]
- **Conformal prediction** - a wrapper that turns any model's outputs into prediction sets or intervals with a guaranteed coverage rate, assuming exchangeable data. [[conformal-prediction-and-uncertainty]]
- **Confusion matrix** - a table of predicted versus true classes from which precision, recall and related metrics are computed. [[model-evaluation-and-metrics]]
- **Context engineering** - deciding what goes into a model's context window at each step: instructions, retrieved data, tool results, history and their order. [[context-engineering]]
- **Context precision (RAG)** - a retrieval metric that rewards relevant chunks ranked above irrelevant ones: mean precision@i over the ranks holding relevant chunks. [[rag-evaluation]]
- **Context window** - the maximum number of tokens (prompt plus output) a model can attend to in one call. [[long-context]]
- **Contextual retrieval** - prepending a short, generated description of a chunk's place in its document before embedding and indexing it. [[advanced-rag]]
- **Contrastive learning** - learning representations by pulling embeddings of matching pairs together and pushing non-matching pairs apart. [[contrastive-learning-infonce-from-scratch-numpy]]
- **ControlNet** - an add-on network that conditions a diffusion model on structure such as edges, depth or pose. [[image-editing-and-controlnet]]
- **Convolution** - sliding a small learned kernel over an input and taking dot products; stride, padding and dilation set the output size. [[convolution-arithmetic-and-receptive-field]]
- **Cosine similarity** - the cosine of the angle between two vectors; the usual similarity for embeddings. [[distance-metrics-and-similarity]]
- **Cross-entropy** - the expected negative log-probability a model assigns to the true outcomes; the standard classification and language-model loss. [[information-theory-for-ml]]
- **Cross-origin isolation** - a page state set by COOP and COEP headers that unlocks SharedArrayBuffer, needed for multi-threaded WebAssembly inference in the browser. [[in-browser-llm-inference]]
- **Cross-validation** - estimating performance by training and testing on several different splits of the data and averaging. [[data-leakage-and-validation-splits]]
- **CTC (connectionist temporal classification)** - a loss that aligns unsegmented input frames to a shorter label sequence using a blank symbol; used in speech recognition. [[sequence-to-sequence-and-ctc]]
- **CUDA** - NVIDIA's GPU computing platform; the driver, CUDA runtime and framework build must be compatible. [[gpu-cuda-setup]]
- **Curse of dimensionality** - in high dimensions data becomes sparse and distances concentrate, so neighbourhood-based methods degrade. [[curse-of-dimensionality]]
- **CUSUM** - a change-detection method that accumulates deviations from a target mean and alarms when the sum crosses a threshold. [[cusum-change-point-detection-from-scratch]]

## D

- **Data augmentation** - creating label-preserving variants of training examples (crops, flips, noise, paraphrases) to improve generalization. [[data-augmentation]]
- **Data leakage** - information that would not be available at prediction time reaching training or validation, which inflates measured performance. [[data-leakage-and-validation-splits]]
- **DataLoader** - the PyTorch component that batches, shuffles and loads samples in parallel worker processes. [[data-loading-pipelines]]
- **DBSCAN** - density-based clustering that grows clusters from core points with enough neighbours and labels sparse points as noise. [[clustering]]
- **DDP (distributed data parallel)** - each GPU holds a full model copy, processes part of the batch and averages gradients with the others. [[distributed-training]]
- **DDPM** - denoising diffusion probabilistic model: learns to predict the noise added at each step of a fixed noising process. [[ddpm-diffusion-from-scratch-numpy]]
- **Debugging training** - systematic checks (overfit one batch, inspect loss and gradients, data sanity) when a network will not learn. [[debugging-neural-network-training]]
- **Decision tree** - a model that splits the data by feature thresholds into a tree of if-else rules with a prediction at each leaf. [[decision-trees-and-random-forests]]
- **Decoding** - turning a model's next-token probabilities into text: greedy, sampling with temperature/top-p, or beam search. [[decoding-and-sampling]]
- **Deep research agent** - an agent that runs many web searches and reads sources over several steps to write a cited report. [[web-search-and-grounding]]
- **DeepSeek** - a Chinese lab's family of LLMs, many released as open weights, including reasoning and MoE models. [[deepseek]]
- **Depth estimation** - predicting a per-pixel distance map from images, often from a single image. [[depth-estimation]]
- **Differential privacy** - a guarantee, tuned by epsilon, that a result changes little whether or not any one person's data is included. [[federated-learning-and-differential-privacy]]
- **Diffusion language model** - a text model that generates by iteratively denoising (unmasking) many tokens in parallel instead of one token at a time. [[diffusion-language-models]]
- **Diffusion model** - a generative model that learns to reverse a gradual noising process, producing samples by denoising from pure noise. [[diffusion-models]]
- **Dimensionality reduction** - mapping data to fewer dimensions while keeping its structure, for visualization, compression or denoising (PCA, UMAP). [[dimensionality-reduction]]
- **Disaggregated serving (prefill/decode disaggregation)** - running prompt prefill and token decode on separate inference instances and shipping the KV cache between them, so TTFT and inter-token latency can be tuned separately. [[disaggregated-prefill-and-kv-cache-offloading]]
- **Distance metric** - a function measuring dissimilarity between points, such as Euclidean, Manhattan or cosine distance. [[distance-metrics-and-similarity]]
- **Distillation (knowledge)** - training a smaller student model to match a larger teacher's outputs or soft probabilities. [[knowledge-distillation-and-compression]]
- **Docker GPU image** - a container image built on a CUDA base image so a model runs with GPU access under the NVIDIA container toolkit. [[docker-for-ml]]
- **Document layout analysis** - detecting regions such as text blocks, tables and figures on a page, and recovering table structure. [[document-layout-and-table-extraction]]
- **Document parsing** - converting PDFs and Office files into clean text, tables and structure an LLM can use. [[document-parsing]]
- **Double descent** - test error falling, rising near the interpolation point, then falling again as model size or training grows. [[generalization-in-deep-learning]]
- **DPO (direct preference optimization)** - aligning a model on preference pairs with a classification-style loss, without a separate reward model or RL loop. [[rlhf-and-preference-optimization]]
- **DQN (deep Q-network)** - Q-learning with a neural network, stabilized by a replay buffer and a target network. [[dqn-from-scratch-numpy]]
- **Dropout** - randomly zeroing activations during training so the network cannot rely on any single unit; off at inference. [[regularization-in-deep-learning]]
- **DSPy** - a framework that defines LLM pipelines as modules with signatures and optimizes their prompts and examples against a metric. [[dspy-and-prompt-optimization]]
- **Dual writes** - writing every insert or update to both the old and the new index during a migration so the backfill only covers pre-existing data. [[embedding-model-migration-and-reindexing]]
- **DuckDB** - an in-process analytical SQL database that queries Parquet, CSV and DataFrames directly. [[polars-and-duckdb-for-ml]]
- **Durable execution** - running a long workflow so that its progress is checkpointed and it resumes after crashes instead of restarting. [[long-running-agents]]
- **Dynamic request batching** - a server queues single requests and runs the model on a list once a size cap or wait timeout is reached, trading a little latency for throughput. [[ray-serve-bentoml-and-litserve]]
- **Dynamic time warping (DTW)** - a distance between sequences that aligns them by stretching time, so similar shapes at different speeds match. [[dynamic-time-warping-from-scratch]]

## E

- **EAGLE (speculative decoding)** - a small draft head that predicts the target model's next features from its hidden states, used as the proposer in speculative decoding. [[speculative-decoding-in-serving]]
- **Early stopping** - halting training when validation performance stops improving, to avoid overfitting. [[regularization-in-deep-learning]]
- **Edge inference** - running a model on the device (phone, browser, embedded board) instead of a server, for latency, privacy or cost. [[edge-on-device]]
- **Einsum** - Einstein-summation notation for tensor contractions, writing products and sums by index letters. [[tensor-shapes-broadcasting-and-einsum]]
- **ELBO** - the evidence lower bound a VAE maximizes: reconstruction likelihood minus the KL divergence of the latent posterior from the prior. [[vae-from-scratch-numpy]]
- **Elo rating** - a rating updated after each pairwise comparison according to how surprising the result was. [[elo-and-bradley-terry-leaderboard-from-scratch]]
- **EM algorithm** - expectation-maximization: alternate between inferring hidden variables and re-fitting parameters to maximize likelihood. [[gaussian-mixture-models-and-em]]
- **Embedding** - a dense vector representation of text, images or other data where similar items lie close together. [[embeddings]]
- **Embedding model** - a model whose output is an embedding, used for search, clustering and RAG retrieval. [[embedding-models]]
- **Embedding model migration** - moving a live vector index to a new embedding model by re-embedding the corpus beside the old index and cutting over atomically. [[embedding-model-migration-and-reindexing]]
- **Ensemble** - combining several models' predictions (voting, averaging, stacking) to beat any single one. [[ensemble-methods]]
- **Entropy** - the average uncertainty of a probability distribution, in bits or nats. [[information-theory-for-ml]]
- **Epoch** - one full pass over the training data. [[deep-learning-training]]
- **Eval (LLM evaluation)** - a repeatable test set plus scoring method that measures whether an LLM application does its job. [[llm-evaluation]]
- **Eval-driven development** - writing evals before changing prompts or models, and accepting a change only when the eval scores hold or improve. [[llm-as-judge-and-eval-driven-development]]
- **Evolution strategies** - black-box optimization that perturbs parameters randomly and moves toward the perturbations that scored best. [[black-box-and-evolutionary-optimization]]
- **Experiment tracking** - logging each training run's parameters, metrics, code version and artifacts so runs can be compared and reproduced. [[experiment-tracking]]
- **Exploding gradients** - gradients growing very large through many layers or time steps, causing unstable training; fixed with clipping and normalization. [[vanishing-and-exploding-gradients]]
- **Exploratory data analysis (EDA)** - inspecting distributions, missing values and relationships in the data before modelling. [[exploratory-data-analysis]]
- **Exponential backoff with jitter** - waiting a randomized, exponentially growing and capped delay between retries so clients that failed together do not retry together. [[llm-api-rate-limits-and-retries]]

## F

- **F1 score** - the harmonic mean of precision and recall. [[model-evaluation-and-metrics]]
- **Face recognition** - identifying or verifying a person by comparing an embedding of their face against stored embeddings. [[face-and-pose]]
- **Faithfulness (RAG)** - share of an answer's claims supported by the retrieved context; measures hallucination independently of whether the answer is correct. [[rag-evaluation]]
- **FastAPI** - a Python web framework commonly used to wrap a model or LLM call in an async HTTP API. [[serving-with-fastapi]]
- **FastICA** - independent component analysis that separates mixed signals by maximizing the non-Gaussianity of the recovered sources. [[fastica-from-scratch]]
- **Feature engineering** - building informative input features from raw data, guided by domain knowledge. [[feature-engineering]]
- **Feature importance** - a measure of how much each input feature contributes to a model's predictions. [[model-interpretability]]
- **Feature scaling** - putting features on comparable scales (standardization, min-max) so distance- and gradient-based models behave well. [[feature-scaling-and-normalization]]
- **Feature selection** - keeping only the inputs that help prediction, to reduce overfitting, cost and complexity. [[feature-selection]]
- **Feature store** - a system that serves the same feature values to training (offline, point-in-time correct) and to live inference (online). [[feature-stores]]
- **Federated learning** - training a shared model across devices or organizations that keep their raw data local and send only updates. [[federated-learning-and-differential-privacy]]
- **Few-shot prompting** - putting a handful of worked input-output examples in the prompt to show the model the task. [[prompt-engineering]]
- **Figma MCP** - an MCP server that gives an agent read access to Figma designs so it can turn them into code. [[design-tools-for-claude]]
- **Fill-in-the-middle (FIM)** - a code-model mode that generates the missing code between a given prefix and suffix. [[code-models]]
- **Fine-tuning** - continuing to train a pretrained model on task-specific data to change its behaviour or style. [[fine-tuning-and-peft]]
- **FlashAttention** - an exact attention kernel that processes tiles in fast on-chip memory with an online softmax, avoiding storing the full attention matrix. [[attention-variants-and-efficient-attention]]
- **Flow matching** - training a generator to predict the velocity that moves noise toward data along a simple (often straight) path, then sampling by integrating an ODE; rectified flow straightens the paths for few-step sampling. [[flow-matching-and-rectified-flow]]
- **Focal loss** - a cross-entropy variant that down-weights easy examples so training focuses on hard, often rare, ones. [[focal-loss-from-scratch-numpy]]
- **Foundation model** - a large model pretrained on broad data and adapted to many downstream tasks by prompting or fine-tuning. [[pretraining-and-scaling-laws]]
- **FP8** - 8-bit floating-point formats (E4M3, E5M2) used for weights, activations or the KV cache on GPUs with FP8 tensor cores, roughly halving memory against BF16. [[quantizing-llms-for-serving]]
- **FSDP (fully sharded data parallel)** - data parallelism that shards parameters, gradients and optimizer state across GPUs to fit larger models. [[distributed-training]]
- **FT-Transformer** - a transformer for tables that embeds each feature as a token; one of the deep-learning alternatives to gradient boosting on tabular data. [[deep-learning-for-tabular-data]]

## G

- **GAM (generalized additive model)** - a model that sums smooth per-feature functions, staying interpretable while capturing non-linear effects. [[generalized-additive-models-and-splines]]
- **GAN (generative adversarial network)** - a generator and a discriminator trained against each other until the generator's samples look real. [[generative-adversarial-networks]]
- **Gaussian mixture model** - a density model that represents data as a weighted sum of Gaussians, fitted with EM; gives soft cluster assignments. [[gaussian-mixture-models-and-em]]
- **Gaussian process** - a distribution over functions defined by a kernel; gives regression predictions with uncertainty. [[bayesian-and-gaussian-processes]]
- **Gaussian splatting** - representing a 3D scene as many coloured 3D Gaussians that can be rendered in real time from new viewpoints. [[gaussian-splatting-and-nerf]]
- **Gemini** - Google's family of multimodal LLMs, offered through the Gemini API and Vertex AI. [[google-gemini]]
- **Gemma** - Google's family of open-weight models, related to Gemini research. [[google-gemma]]
- **Generalization** - how well a model performs on data it was not trained on. [[generalization-in-deep-learning]]
- **Generalized linear model (GLM)** - a linear predictor passed through a link function, with a distribution (Poisson, Gamma, Tweedie) suited to the target. [[generalized-linear-models]]
- **Geospatial ML** - machine learning on location data, with spatial features and spatially aware cross-validation. [[geospatial-ml]]
- **GGUF** - the single-file model format used by llama.cpp, holding quantized weights and metadata. [[llama-cpp-gguf]]
- **Gini impurity** - the probability of mislabeling a random sample if labelled by the node's class distribution; a decision-tree split criterion. [[decision-tree-from-scratch]]
- **GNN (graph neural network)** - a network that updates each node's representation by aggregating messages from its neighbours. [[graph-neural-networks]]
- **Goodput** - requests per second an LLM server completes while still meeting its latency targets (TTFT and TPOT); the capacity number that matters, unlike raw tokens per second. [[llm-load-testing-and-benchmarking]]
- **GPT** - OpenAI's family of LLMs, offered through the OpenAI API and Azure. [[openai-gpt]]
- **GPTQ** - a post-training method that quantizes LLM weights layer by layer, using second-order information to compensate the error. [[quantization]]
- **GPU cloud** - renting GPUs from hyperscalers, specialist GPU clouds or serverless GPU platforms. [[gpu-cloud-options]]
- **GQA (grouped-query attention)** - attention where groups of query heads share one key-value head, shrinking the KV cache. [[attention-variants-and-efficient-attention]]
- **Gradient accumulation** - summing gradients over several small batches before one optimizer step, to emulate a larger batch in limited memory. [[efficient-training-mixed-precision]]
- **Gradient boosting** - building an ensemble of trees one at a time, each fitted to the errors of the ensemble so far; strong default for tabular data. [[gradient-boosting-tabular]]
- **Gradient checkpointing** - storing only some activations in the forward pass and recomputing the rest during backprop, trading compute for memory. [[efficient-training-mixed-precision]]
- **Gradient clipping** - capping the gradient norm or values before the update to prevent exploding-gradient steps. [[vanishing-and-exploding-gradients]]
- **Gradient descent** - minimizing a loss by repeatedly stepping parameters against its gradient; stochastic and mini-batch variants use subsets of data. [[gradient-descent]]

- **Reciprocal rank fusion (RRF)** - combining ranked lists by summing 1/(k + rank) per item; needs no score calibration. [[reciprocal-rank-fusion-from-scratch]]
- **Recommender system** - a system that predicts which items a user will want, from interactions, content or both. [[recommender-systems]]
- **Red-teaming** - deliberately attacking a model or LLM app with adversarial prompts to find failures before users do. [[red-teaming-llm-apps]]
- **Regularization** - techniques that reduce overfitting by constraining a model: weight decay, dropout, early stopping, augmentation. [[regularization-in-deep-learning]]
- **Reinforcement learning** - learning a policy from rewards received by acting in an environment. [[reinforcement-learning]]
- **Remote sensing** - analyzing satellite or aerial imagery, often multispectral, for mapping and change detection. [[satellite-and-remote-sensing]]
- **Reranker** - a model, usually a cross-encoder, that rescores a shortlist of retrieved documents against the query for better ordering. [[rerankers]]
- **Residual analysis** - examining prediction errors of a regression model for patterns that reveal missing structure. [[regression-metrics-and-residual-analysis]]
- **Residual connection** - adding a layer's input to its output, so very deep networks train well. [[residual-and-skip-connections]]
- **Retry-After** - an HTTP response header giving how long a client should wait before retrying, sent with 429 and some 5xx responses. [[llm-api-rate-limits-and-retries]]
- **Reward model** - a model trained, usually on human preferences, to score outputs; used as the signal in RLHF. [[reward-modeling-and-verifiers]]
- **Ridge and lasso** - linear regression with an L2 penalty (ridge, shrinks weights) or L1 penalty (lasso, sets some to zero). [[linear-models]]
- **RLHF** - reinforcement learning from human feedback: fine-tune a model against a reward model trained on human preference comparisons. [[rlhf-and-preference-optimization]]
- **RLVR** - reinforcement learning with verifiable rewards: RL on tasks whose answers can be checked automatically, such as math or unit tests. [[rl-with-verifiable-rewards]]
- **RMSNorm** - layer normalization that rescales by the root mean square only, without subtracting the mean. [[normalization-layers]]
- **RNN (recurrent neural network)** - a network that processes a sequence step by step, carrying a hidden state forward. [[cnn-and-rnn-architectures]]
- **ROCm** - AMD's open GPU compute stack (driver, runtime, math libraries) that PyTorch, vLLM, llama.cpp and Ollama use on AMD GPUs. [[amd-rocm-setup]]
- **RoPE (rotary position embedding)** - encodes position by rotating query and key vectors by position-dependent angles, so attention depends on relative distance. [[rope-rotary-embeddings-from-scratch-numpy]]
- **ROUGE** - a summarization metric based on n-gram or longest-common-subsequence overlap with reference summaries, recall-oriented. [[bleu-and-rouge-from-scratch]]

## S

- **safetensors** - a safe, fast file format for model weights that, unlike pickle, cannot execute code on load. [[model-checkpointing-and-export]]

- **Saliency map** - an image showing which input pixels most affect a model's prediction, typically from gradients. [[saliency-maps-and-neural-attribution]]
- **SAM (Segment Anything)** - a promptable segmentation model that returns masks for points, boxes or (in later versions) text prompts, in images and video. [[segment-anything-sam2]]

- **Sandboxed code execution** - running model-written code in an isolated environment with limited files, network and resources. [[sandboxed-code-execution]]
- **Scaling laws** - empirical power laws relating loss to model size, data and compute, used to plan training runs. [[pretraining-and-scaling-laws]]
- **Segmentation** - labelling image pixels by class (semantic) or by object instance (instance). [[segmentation]]
- **Self-attention** - attention where queries, keys and values all come from the same sequence. [[self-attention-from-scratch-numpy]]
- **Self-consistency** - sampling several reasoning paths and taking the majority final answer. [[self-consistency-voting-from-scratch]]
- **Self-supervised learning** - learning representations from labels derived from the data itself, such as masked or next tokens. [[autoencoders-and-self-supervised-learning]]
- **Semantic caching** - returning a stored LLM answer when a new query is similar enough in embedding space to an earlier one. [[semantic-caching]]
- **Semantic chunking** - splitting text where the embedding distance between adjacent sentences jumps, so chunks follow topic changes. [[semantic-chunking-from-scratch]]
- **Semi-supervised learning** - training with a few labeled examples plus many unlabeled ones. [[semi-supervised-and-active-learning]]
- **Seq2seq** - an encoder-decoder model that maps an input sequence to an output sequence of a different length. [[sequence-to-sequence-and-ctc]]
- **SGLang** - an LLM serving engine with prefix-sharing (RadixAttention) and structured-generation support. [[sglang-and-tensorrt-llm]]
- **Shadow deployment** - running a new model on live traffic alongside the current one without serving its outputs, to compare them safely. [[ab-testing-and-canary-for-models]]
- **SHAP** - per-prediction feature attributions based on Shapley values from game theory. [[model-interpretability]]
- **Sinkhorn algorithm** - fast entropy-regularized optimal transport by alternately normalizing rows and columns of a kernel matrix. [[sinkhorn-optimal-transport-from-scratch]]
- **Sleep mode (vLLM)** - releasing a running vLLM engine's GPU memory (weights offloaded or discarded, KV cache dropped) without stopping the server, then waking it later. [[model-weight-loading-and-cold-starts]]
- **SLIC superpixels** - grouping pixels into compact regions by local k-means in colour plus position space. [[slic-superpixels-from-scratch]]
- **Small language model (SLM)** - a compact LLM sized to run on laptops, phones or edge devices. [[small-language-models]]
- **SMOTE** - oversampling a minority class by interpolating new synthetic points between its nearest neighbours. [[smote-from-scratch]]
- **Softmax** - turns a vector of scores into a probability distribution by exponentiating and normalizing. [[activation-functions]]
- **Sparse autoencoder (interpretability)** - an autoencoder with a sparsity penalty trained on a model's activations to find human-interpretable features. [[sparse-autoencoders-for-interpretability]]
- **Speaker diarization** - segmenting audio by who is speaking ("who spoke when"). [[speaker-diarization]]
- **Spectral clustering** - clustering using eigenvectors of a similarity graph's Laplacian, which finds non-convex clusters. [[spectral-clustering-from-scratch]]
- **Spectral subtraction** - denoising audio by subtracting an estimate of the noise spectrum from each frame. [[spectral-subtraction-denoising-from-scratch]]
- **Speculative decoding** - a small draft model proposes several tokens that the large model verifies in one pass, keeping its output distribution while generating faster. [[speculative-decoding-from-scratch-numpy]]
- **Speech translation** - turning speech in one language into text or speech in another. [[speech-translation]]
- **Speech-to-speech model** - a model that takes audio in and produces audio out directly, without separate STT and TTS steps. [[speech-to-speech-realtime-models]]
- **Speech-to-text (ASR)** - automatic speech recognition: transcribing spoken audio into text. [[speech-to-text]]
- **Splines** - piecewise polynomials joined smoothly at knots, used to model non-linear effects of a feature. [[generalized-additive-models-and-splines]]
- **Stacking** - training a meta-model on the out-of-fold predictions of several base models. [[ensemble-methods]]
- **State space model** - a sequence model built on a linear recurrence over a hidden state, computable in linear time (S4, Mamba). [[state-space-models]]
- **Steering vector** - a residual-stream direction added to (or projected out of) a model's activations at inference to change its behaviour without training. [[refusal-direction-and-abliteration]]
- **STFT (short-time Fourier transform)** - Fourier transforms of short overlapping windows, giving a spectrogram of audio over time. [[mel-spectrogram-and-mfcc-from-scratch]]
- **Stratified split** - a train/test split that preserves each class's proportion in every fold. [[data-leakage-and-validation-splits]]
- **Streaming (LLM)** - sending generated tokens to the client as they are produced (often over server-sent events) instead of after completion. [[streaming-and-async-llm-apps]]
- **Streaming ML pipeline** - computing features and predictions on event streams (such as Kafka) in near real time. [[streaming-ml-pipelines]]
- **Structured output** - constraining a model to return data matching a JSON schema or typed model, such as Pydantic. [[structured-output]]
- **Supervised learning** - learning a mapping from inputs to known labels. [[ml-fundamentals]]
- **Survival analysis** - modelling time until an event, accounting for subjects whose event has not happened yet (censoring). [[survival-analysis]]
- **SVM (support vector machine)** - a classifier that finds the maximum-margin boundary between classes, optionally via a kernel. [[svm-knn-naive-bayes]]
- **Synthetic data** - training or evaluation data generated by models or simulators rather than collected. [[synthetic-data-for-llm-training]]
- **System prompt** - the instruction block that sets a model's role, rules and context for the whole conversation. [[prompt-engineering]]

## T

- **Target encoding** - replacing a category with the (regularized, out-of-fold) mean of the target for that category. [[categorical-encoding]]
- **Temperature** - a sampling parameter that divides logits before softmax; lower values make output more deterministic, higher more varied. [[decoding-and-sampling]]
- **Tensor** - a multi-dimensional array; shapes and broadcasting rules decide how operations combine them. [[tensor-shapes-broadcasting-and-einsum]]
- **TensorRT-LLM** - NVIDIA's library for compiling and serving LLMs with optimized kernels on NVIDIA GPUs. [[sglang-and-tensorrt-llm]]

- **Text-to-SQL** - translating a natural-language question into a SQL query over a known schema. [[text-to-sql]]

- **Transfer learning** - reusing a model trained on one task or domain as the starting point for another. [[transfer-learning-and-domain-adaptation]]
